# Documentation Policy

Status: AUTHORITATIVE

Documentation must describe actual state. Never present planned work as implemented, an unexecuted check as passed, unsupported compatibility as verified, or an invented source/decision as fact.

Keep authoritative contracts, explanation, and historical/evidence artifacts visibly distinct. README is an entry point, not a governance duplicate. Keep changes scoped to the affected subject. Preserve license, copyright, attribution, and historical decision text unless explicitly authorized.

The project context selects natural language. Technical identifiers and established terms retain canonical spelling. Source-based work must distinguish primary/secondary sources, empirical findings, inferences, assumptions, and uncertainty. Update, deprecate, supersede, or archive stale material rather than silently rewriting history.
